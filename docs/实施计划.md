## 二、产品选择

暂定为“选股条件工作台”。目标用户是假设具备基本股票知识、但难以把选股想法准确转换为数据指标的个人研究者；这是产品设计假设，尚无用户研究验证。

核心价值：把一句模糊描述变成可检查、可编辑、可执行、可复算的策略，并解释哪些股票符合、哪些不符合、哪些因数据不足无法判断。

示例输入：“想看看经营改善、估值合理、走势相对稳定的 A 股。”

用户路径：

1. 输入意图，查看已识别目标与尚有歧义的部分。
2. 用简短选项澄清股票范围、经营改善定义、估值口径和稳定性窗口；能从输入确定的内容不重复询问。
3. 查看 AI 建议条件，逐项修改字段、运算符、阈值和窗口；确认后执行。
4. 若条件冲突，在相应条件旁解释原因，支持手动修改或显式接受修复建议，再执行。
5. 在入选、排除、无法判断三个结果视图中查看股票和逐条件证据。
6. 修改一个条件，以同一数据快照重新筛选，查看新增、移除、保留和状态变化原因。
7. 保存策略，重新载入后仍可编辑和执行；支持导出不含密钥的策略 JSON。

第一版完成比较和保存，不扩展回测或定时监控。题目列出的这些后续操作采用“比较 + 保存”实现，剩余方向在 README 明确说明未做。

## 四、页面结构与交互

一个工作台承载主任务，减少跳转：

- 顶部：产品名称、当前股票范围、数据时点与接入状态。
- 条件区：意图输入、澄清问题、可编辑条件卡、冲突信息和执行按钮。
- 结果区：入选/排除/无法判断数量、覆盖情况、表格、排序及快照信息。
- 证据侧栏：点击股票，展开逐条件实际值、阈值、结论、来源及计算口径。
- 策略与比较视图：保存列表、载入/导出、条件差异与结果集合变化。

视觉方向采用适合数据阅读的浅色工作台、蓝色主操作、清晰表格和层级。优先保证中文可读性与数值对齐，避免依赖远程字体。颜色仅辅助表达状态，始终配文字与图标；涨跌色与筛选通过/失败色不混用。

交互要求：加载与超时可见；字段旁显示错误；关键操作支持键盘与可见焦点；移动端分段展示条件和结果，不依赖悬停。无数据时不得展示虚构候选列表。

设计参考：ui-ux-pro-max 检索的 Data-Dense Dashboard 风格适合金融分析表格；其同时返回的 Enterprise Gateway 营销页结构与任务不符，未采用。本节是经任务筛选后的设计建议，不是现成页面或用户验证结论。

## 五、数据与模型接入优先验证

### 当前证据

- [iFinD 官方入口](https://mcp.51ifind.com/?syncCookieTimes=1)可读内容介绍了行情、财务、公告和宏观数据服务；当前未验证具体 MCP 工具、授权、配额或实际调用。
- [扶摇文档入口](https://fuyao.aicubes.cn/docs/)本次通过网页读取工具打开失败；不能据此判断网站、API 或账号权限不可用。
- 本次工具目录未发现可直接调用的扶摇或 iFinD 专用工具；后续核验官方接入方式。聊天中的工具可用不等于部署后的 Web 服务可用，必须在产品服务端单独验证。

### 接入检查与决策

1. 确认真实可用的数据授权、模型接口、服务端连接方式及最小成功响应；密钥仅在环境变量中配置。
2. 确认股票池、财务字段、估值字段、历史行情、交易日和复权口径，建立字段映射。
3. 优先选择一个明确的指数成分股票池作为第一版范围；具体指数在覆盖与配额验证后决定。界面不得宣称完成全 A 股筛选。
4. 先覆盖经营、估值、走势三类最小指标；不支持的指标显式提示，不擅自替换。
5. 如果第一阶段仍无法访问真实数据，立即记录阻塞，并继续使用明确标识的构造数据实现引擎和异常测试；真实数据主链路保持未完成状态。可公开展示的真实快照必须先核验来源、时点和授权，不能静默降级。

具体指标示例是收入或利润变化、正值 PE（需明确口径）、指定窗口波动/回撤。以上不是已验证可用字段；阈值由用户确认，不把“PE 小于某数”当作普遍合理估值。

经营变化需考虑报告期、累计口径与异常基数；历史行情需考虑复权、停牌和样本不足。不同来源或口径冲突时显示冲突，不能静默选择更有利数值。

### AI 接入边界

AI 只接收任务所需的输入、已支持指标目录和受约束证据；输出须经过结构、字段白名单、单位和范围校验。模型不得执行任意代码、SQL 或自造接口参数。

澄清与解释可以由模型生成；最终入选状态、数值与条件比较必须由程序计算。解释中的数值来自证据引用，避免生成不可复算数字。模型不可用或返回无效结构时，明确告知并允许用户手动配置条件，不把规则匹配冒充模型输出。

## 六、技术方案建议

建议使用 Next.js + TypeScript 的单应用结构，界面与服务端 API 在同一提交目录，减少开发与部署环节。[Next.js Route Handlers 官方文档](https://nextjs.org/docs/app/getting-started/route-handlers)支持在应用内定义服务端请求处理。具体依赖版本在初始化时核验并锁定。

规划结构（未创建的路径不代表功能存在）：

```text
src/
  app/                 页面、布局、服务端 API
  components/          条件编辑、结果表格、证据与比较
  domain/              条件/证据契约、校验、筛选和差异计算
  server/
    ai/                模型调用、提示词、响应校验
    providers/         数据适配器、口径映射和异常处理
tests/
  unit/                确定性逻辑与边界
  integration/         适配器与模型失败处理
  e2e/                 浏览器主链路
docs/                  题目、计划、AI 记录、测试、交付说明
public/                可公开静态资源
artifacts/             可提交的截图、测试摘要和可选视频
.env.example           空值或占位值环境变量说明
README.md              安装、运行、设计、数据及交付入口
```

首版策略保存在当前浏览器，明确提示不跨设备、不跨用户同步；提供导出/导入避免只依赖本地存储。策略保存条件及版本，重新执行默认获取当前数据；结果版本比较使用同一有效快照，快照不可用时提示重新运行基线。是否允许保存金融数据取决于授权，不把受限数据混入导出文件。

服务端校验所有条件和来源；公开部署增加输入长度、请求频率、调用超时和股票池规模限制。日志过滤密钥与用户输入中的敏感信息。部署平台在验证账户、连接方式与数据网络可达性后选择；不预设已经具备托管权限。

## 八、关键验收用例

1. 模糊意图经过必要澄清得到具体条件，用户修改阈值后执行。
2. 同一指标同时要求大于 20 且小于 10，执行前提示冲突；修复后通过。
3. 同快照、同条件版本重复计算，结果完全一致。
4. 明确失败条件导致排除，同时展示其他缺失项；没有失败但有未知时为无法判断；全通过才入选。
5. 负 PE、异常同比基数、行情样本不足、不同窗口或口径不可直接比较。
6. 超时、鉴权失败、配额限制、部分字段缺失、空股票池和过期数据均显式呈现。
7. 修改条件后结果差异来自条件变化；若刷新数据则单独说明，不能混用旧基线。
8. 策略保存、刷新、载入、导出、导入后条件含义一致，损坏文件有可理解的错误提示。
9. 模型虚构字段、错误结构、提示注入，以及“保证上涨”“直接买哪只”等请求不会突破产品边界。
10. 公网 URL 能完成主链路；打包目录独立安装、运行，构建和浏览器操作均验证；检查客户端包、日志和提交内容不含密钥。

自动化测试优先覆盖有业务风险的确定性逻辑和故障路径；浏览器验收覆盖用户实际操作。不把构造数据测试、页面截图、构建通过或模型自述等同于真实接口与公网主链路验证。
