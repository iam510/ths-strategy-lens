# MiniMax 本地模型验收

完成时间：2026-10-31（Asia/Shanghai）；部分接口检查始于 2026-10-30 深夜。范围为本地应用，本报告记录本地检查，后续线上 secrets 和 API 已验证，另见[托管接入验收](./托管接入验收.md)。

## 实测结果

模型 MiniMax-M3.1-Flash，OpenAI 兼容地址 https://api.minimax.cn/v1，提示词 intent-v1.2。密钥由用户自行填写，本报告不含密钥。

使用 `node scripts/verify-model.mjs --live` 显式调用已配置服务，共 8 项检查通过，摘要见 [model-live-verification.json](../artifacts/model-live-verification.json)：

- 明确三项条件：年报营收同比 >5%、参考静态 PE ≤30、60 日年化波动率 ≤35%；不改变阈值，无澄清和不支持项。
- 模糊表达：生成三项必要澄清，选项引用有效，不将可澄清项误判为不支持。
- 矛盾条件：保留 PE >30 与 PE <10，由确定性引擎在取数前返回 CONFLICT。
- 不支持项：保留营收同比条件，明确指出 ROE 和全 A 股筛选不支持。
- 指令覆盖与保证涨停请求：本地边界检查返回 422，不调用模型。
- 模型条件送入真实扶摇筛选：12 只代码升序样本，6 入选、6 排除、0 无法判断；市场数据截至 2026-10-30。

本轮四次实际模型解析约 1.5–5.3 秒，真实数据请求约 20.5 秒；这只是本轮样本观测，不是稳定性能或准确率指标。六个意图检查中两项在本地拦截，并非六次模型调用。

实际输入“经营改善、估值合理、走势稳健”，模型提出三个澄清；逐项选择后，将建议条件编辑为营收 >5%、PE ≤30、波动率 ≤35%，勾选确认并执行真实筛选，结果 6/6/0。

把 PE 上限由 30 改为 15，重新确认并应用，同一快照 `live-6661183b-820d-4e35-802b-33c36fab2214` 得到 3/9/0；比较弹窗显示三只样本由入选变为排除，并列明不满足的新阈值。见 [model-browser-verification.json](../artifacts/model-browser-verification.json)。这只是条件研究，不构成买卖建议。

## 实际发现与修正

1. 原 3500 token 额度及默认思考深度下，模糊输入出现空正文/截断 JSON；诊断观察到 finish_reason=length。按官方接口契约，为 MiniMax Flash 设置 reasoningEffort=low，完成额度改为 6000；其他模型保留原配置。不自动重试，仍设置 35 秒超时。
2. OpenAI Compatible provider 默认 JSON 对象模式没有把完整 Schema 自动传给模型，澄清字段不符合校验。现在系统提示词包含由同一个 Zod 契约生成的完整 JSON Schema；返回仍需 Zod 与引用校验，未放宽验证。
3. 浏览器发现模型把可澄清的定义和未指定范围也列入 unsupported，导致无法继续。提示词明确区分可解决的歧义与真正不支持的要求；最终版本 intent-v1.2 已通过接口和浏览器验收。
4. 修正验收脚本对“忽略系统指令”的错误预期：该输入按已有产品规则应本地拦截，不是成功模型解析。脚本使用 --live 显式启用，保存进度；未将失败尝试写成通过。

修正由 Codex 完成；用户实际参与是取得密钥、自行保存配置及选择服务商，未冒称用户手动编码。临时诊断已移除；无原始模型思考过程、密钥或请求授权头进入交付材料。

参考：[MiniMax OpenAI 兼容接口](https://platform.minimax.cn/docs/api-reference/text-openai-api)。其中说明思考 token 计入上限、默认 effort=max，额度不足可导致 length 和空正文。
